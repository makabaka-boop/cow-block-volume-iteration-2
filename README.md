# vfs — Go HTTP 虚拟文件卷

固定块大小、块共享、写时复制（COW）、稀疏文件、配额与乐观并发控制的内存虚拟文件卷，
通过 HTTP 暴露。

- 块大小 `BlockSize = 4096` 字节
- 全卷物理块上限 `MaxBlocks = 1024`（4 MiB 物理容量）
- 文件名：唯一 ASCII（字母/数字开头，其后允许字母数字 `.` `_` `-`，1–255 字节）
- 乐观并发：所有变更必须携带“预期卷修订号” `rev`，提交成功后返回新修订号

## 设计

- 物理块存于 `map[blockID]*pblock`，每个块带引用计数 `refs`；引用归零即回收进
  freelist 复用，因此 `len(blocks)` 永远等于当前真实占用的物理块数。
- 每个文件是一张稀疏映射 `逻辑块号 -> 物理块ID`。缺失的逻辑块是稀疏洞，读为零、
  不占物理空间。
- **克隆**只复制映射表，对每个共享块 `refs++`，克隆瞬时完成且不分配数据块。
- **写时复制**：写入命中的块若 `refs > 1`，先复制一份再改私有副本；`refs == 1`
  或空洞则直接写/新分配。一次写入只分叉真正被触及的块。
- **截断**：缩短时先在“预留阶段”算出将释放与将新分配（跨边界共享块的 COW）的块数，
  再提交；增长只改逻辑长度（尾部是稀疏洞）。非块对齐缩短会把末块尾部清零，若该块被
  共享则先 COW，保证克隆互不影响。
- **删除**逐块递减引用，被克隆共享的块仍然存活。
- **原子性**：所有变更先校验（修订号、范围、名称、配额预留）再提交；任何一步失败都
  不会写入字节、不改变引用计数、不推进修订号。零字节写不是提交，不改变文件和修订号。
- **并发**：单把 `sync.RWMutex` 串行化全部变更；修订号在锁内比较并自增，因此携带同一
  `rev` 的多个并发提交至多一方成功，其余得到修订冲突（HTTP 409）。

物理占用统计：`/stats` 的 `usedBlocks` 统计的是去重后的物理块（共享块只计一次）；
每个文件的 `physicalBlocks` 统计该文件映射的逻辑槽位数，`physicalBytes` 按完整块计算；
`sparseBytes` 统计逻辑文件中没有映射到物理块槽位的字节（末尾部分块只扣减块内仍位于文件中的部分）。
已分配块内部读出为零的字节仍属于该物理块，不计为稀疏洞；因此“内容为零”不等于“稀疏字节”。
同时返回每文件逻辑长度 `length`。

## HTTP 接口

所有变更为 `POST`，用查询参数 `rev`（或请求头 `X-Expected-Revision`）携带预期修订号。
成功返回 `{"revision": <新修订号>}`。

| 方法 & 路径 | 说明 |
|---|---|
| `POST /create?name=&rev=` | 创建空文件 |
| `POST /clone?src=&dst=&rev=` | 克隆（只共享块） |
| `POST /write?name=&offset=&rev=` | 请求体为按偏移覆写的字节，可跨块、可制造稀疏洞；零字节写不扩展文件、不推进修订，偏移越过 EOF 时返回 `416` |
| `POST /truncate?name=&length=&rev=` | 设置逻辑长度 |
| `POST /delete?name=&rev=` | 删除文件并释放引用 |
| `GET  /read?name=&offset=&length=` | 范围读；省略或负 `length` 读到 EOF；`offset+length` 溢出返回 `416` |
| `GET  /stat?name=` | 单文件逻辑长度与物理占用 |
| `GET  /stats` | 全卷占用统计 |

状态码：`200` 成功；`400` 名称/参数错误；`404` 文件不存在；`409` 修订冲突或名字已存在
（错误体区分）；`416` 偏移越界；`507` 物理块配额不足。

读接口成功时返回 `X-Revision` 与 `X-Length` 头；范围/文件错误响应也带当前 `X-Revision`，其值对应错误检查时的卷快照。

## 运行

```bash
go run ./cmd/vfsd -addr :8080
```

## 测试

- `vfs_test.go`：跨块写入、稀疏洞、克隆分叉与 COW、截断/删除释放引用、配额失败的
  原子性、修订冲突、并发同修订单赢家、范围读边界、名称规则。
- `model_test.go`：**朴素模型对拍**。模型为每个文件保存完整字节数组，并用独立的
  引用计数表模拟物理层（写按块分配、克隆共享、截断/删除减引用）。包含确定性场景与
  4 个种子 × 1200 步随机差分测试（创建/克隆/覆写/截断/删除/范围读，含陈旧修订号），
  每步对拍：修订号、去重物理块总数、每文件物理块数与完整文件内容。
- `concurrency_http_test.go`：经真实 HTTP 栈的同修订并发单赢家与请求头传修订号。
